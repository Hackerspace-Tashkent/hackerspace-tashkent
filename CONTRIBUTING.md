# 🤝 Вклад в Hackerspace Tashkent

Мы рады любому вкладу в комьюнити! Вот как можно помочь:

## 📝 Виды вклада

- **Документация** — гайды, туториалы, переводы
- **Код** — PR с исправлениями, фичами, улучшениями
- **Hardware** — схемы, платы, прошивки, документация по железу
- **Организация** — воркшопы, митапы, хакатоны
- **Идеи** — предложения в Issues или Discussions

## 🚀 Как сделать вклад

### 1. Документация и код

1. **Создай форк** этого репозитория
2. **Создай ветку** для своей задачи:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Сделай изменения** и закоммить:
   ```bash
   git add .
   git commit -m "Add: описание изменений"
   ```
4. **Запуш** и создай **Pull Request**

### 2. Предложить идею

- Создай **Issue** с описанием идеи
- Или напиши в **Discussions** для обсуждения

### 3. Сообщить о проблеме

- Создай **Issue** с меткой `bug`
- Опиши проблему, шаги воспроизведения, ожидаемый результат

## 📋 Требования к PR

- **Описание** — что делает этот PR
- **Тестирование** — проверь локально перед отправкой
- **Стиль** — следуй существующему стилю кода/документации
- **Лицензия** — твой вклад распространяется под MIT

## 💬 Общение

- **Вопросы** — [Discussions](../../discussions)

- `help wanted` — нужна помощь

## 🗂 Что мы игнорируем и почему

`.gitignore` есть во всех четырёх репозиториях. Правила не arbitrary — за каждым
набором стоит причина, и менять их нужно осознанно.

### Секреты — никогда

Ключи, токены и пароли не попадают в репозиторий. Это единственное правило,
нарушение которого дорого стоит.

```bash
.env
.env.*
!.env.example
*.pem
*.key
secrets/
credentials/
```

`.env.example` — **единственное исключение**, и оно намеренное: он показывает,
какие переменные нужны, но без значений. Так новичок не гадает, что вписать.

Если секрет всё же попал в коммит — **сначала отзывай ключ**, и только потом
чисти историю. Отозванный ключ безопасен, ключ в истории, который ты «просто
удалил», — нет.

### Переносы строк — чтобы скрипты работали

`check.sh` — это bash. Если файл сохранился с окончаниями CRLF, скрипт падает с
`$'\r': command not found`. Ученик на Windows столкнётся с этим первым.

Поэтому в учебном репозитории лежит `.gitattributes`:

```
* text=auto eol=lf
*.sh text eol=lf
```

В репозитории хранится LF, на Windows в рабочей копии остаётся CRLF. Результат
одинаковый на всех платформах.

### Артефакты сборки

`build/`, `dist/`, `*.o`, `*.elf`, `*.map`, `node_modules/`, `__pycache__/`,
`*.pyc` — это воспроизводимо. Собирается заново в любой момент, хранить в
истории незачем.

### Работа ученика

`labs/**/lab-work/` не игнорируется намеренно — но и не коммитится: это личные
попытки, а не часть курса.

### Прошивка — исключение

`*.bin` и `*.hex` мы **не** игнорируем. Обычно прошивку исключают, но у нас
учебный проект: ученику проще открыть файл прямо из репозитория, чем искать его
в Releases. Если со временем репозиторий разрастётся — перенесём бинарники в
Releases и добавим правило сюда.

### Правило на случай сомнений

Если не уверен, что игнорировать — **не игнорируй**. Лишний файл в истории
исправить легко, потерянную работу — нет.

**Спасибо за вклад! 🙌**
